# Sidequests

Sidequests is a Django web app that hands out small real-life challenges, generated by Google's Gemini models. You take a quest, you have 24 hours to do it, and you come back with a short description of what happened and, optionally, a photo. Over time the app keeps track of what you finished, what you let slip, and which kinds of quests you actually do.

The idea is to add a bit of variety to an ordinary day: take an unfamiliar route, call someone you haven't spoken to in a while, cook something new. When you want more of a push, you can ask for something genuinely hard, like an hour-long run or riding the metro from one end of the city to the other.

## How it works

You can have one active quest at a time. Pressing the button with the default setting asks for an easy or medium quest; the selector next to it lets you pin a difficulty from 1 (very easy) to 5 (very hard). Each level comes with a short description in the prompt, so "very hard" means half a day of real effort rather than whatever the model happens to think it means.

If you don't like a quest, you can reroll it up to three times. Two extra buttons, Easier and Harder, reroll it one difficulty level down or up. Unfinished quests are marked as failed automatically once their deadline passes.

Language models tend to repeat themselves, and early versions of this app handed out the same "take a different route" quest over and over. Two things deal with that now. First, the texts of your quests from the last seven days go into the prompt with a request to suggest something different. Second, every generated quest is turned into an embedding and compared with your recent ones; if it's too close to something you've already had, the app tries again, up to three attempts.

The stats page shows how many quests you completed and failed, your completion rate, the average number of rerolls, and a breakdown of completed quests by category.

## Tech stack

- Python 3.14 and Django 6.0.8
- PostgreSQL 16 with the pgvector extension, for storing embeddings and comparing them by cosine distance directly in SQL
- Gemini API through the `google-genai` SDK, with structured output validated by pydantic; `gemini-embedding-001` for 768-dimensional embeddings
- Celery with Redis as the broker, and `django-celery-beat` for the periodic task that expires overdue quests
- Django's built-in authentication views for login, logout and registration

## Project structure

```
config/          project settings, root URLs, Celery app
quests/
  models.py      Quest and Assignment
  ai.py          prompt building, generation, embeddings, similarity check
  views.py       quest flow, rerolls, completion, stats, registration
  tasks.py       periodic task that marks overdue assignments as failed
  templates/     page templates, including login and registration
```

A `Quest` is the generated text with its difficulty, category and embedding. An `Assignment` is the fact that a particular user took a particular quest: when they took it, when it's due, its status, the proof they submitted and how many rerolls they used.

## Running it locally

You'll need Python 3.14, Docker and a Gemini API key from Google AI Studio.

Clone the repository, create a virtual environment and install the dependencies:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Copy `.env.example` to `.env` and fill in the values: the database credentials, a Django secret key and your `GEMINI_API_KEY`.

Start PostgreSQL with pgvector and Redis in Docker. The database runs on port 5434 to avoid clashing with a local PostgreSQL install:

```bash
docker run -d --name sidequests-db -p 5434:5432 \
  -e POSTGRES_USER=<user> -e POSTGRES_PASSWORD=<password> -e POSTGRES_DB=<dbname> \
  -v sidequests-pgdata:/var/lib/postgresql/data \
  pgvector/pgvector:pg16

docker run -d --name sidequests-redis -p 6379:6379 redis
```

Apply the migrations, which also enable the pgvector extension, and create an admin user:

```bash
python manage.py migrate
python manage.py createsuperuser
```

Then run the web server, the Celery worker and the scheduler, each in its own terminal:

```bash
python manage.py runserver
celery -A config worker -l info --pool=solo
celery -A config beat -l info
```

The `--pool=solo` flag works around a crash in Celery's default process pool with Python 3.14 on macOS. It runs tasks one at a time, which is plenty for a single periodic task.

Finally, open the admin, go to Periodic tasks and add a task for `quests.tasks.expire_overdue_quests` on a crontab schedule such as every five minutes (`*/5 * * * *`). The schedule lives in the database, so you can change it later without touching code or restarting anything.

## A note on API limits

The free Gemini tier allows very few requests per day for the text model, and a single quest can take up to three generation calls if the first attempts turn out too similar to recent ones. If you hit the limit, the app shows a message asking you to try again later instead of failing, and the full error is logged in the server console.
